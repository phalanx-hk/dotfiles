# 変換ルール

`article-summarizer` の出力（または同等構造のプレーン Markdown）を Obsidian 記法に変換する際のマッピング。種別は「決定的（機械的に置換可能）」「半決定的（パターン照合で適用判断）」「判断（Claude が文脈解釈）」の 3 段階。

## マッピング表

| # | 入力パターン | 出力パターン | 種別 |
|---|---|---|---|
| 1 | `# タイトル` 直後の `- 情報源: URL`, `- 著者: 名前`, `- 日付: YYYY-MM-DD` 等の箇条書きブロック | YAML frontmatter に変換し、`title`, `source`, `author`, `date`, `created`, `tags` をフィールド化 | 決定的 |
| 2 | `- 引用: タイトル (著者, 媒体, 日付) URL` のような引用元情報行 | frontmatter には入れず、本文先頭に `> [!cite] 引用元`<br>`> タイトル — 著者 (媒体, 日付)`<br>`> [リンク](URL)` の callout を配置 | 決定的 |
| 3 | `![desc](images/figure.jpg)`（Vault 内相対パス画像） | `![[images/figure.jpg\|desc]]`。desc が空なら `![[images/figure.jpg]]` | 決定的 |
| 4 | `![desc](https://...)`（外部 URL 画像） | そのまま標準 Markdown 形式を維持（Obsidian embed は Vault 内パスのみ対応） | 決定的 |
| 5 | `[anchor](https://...)` の外部リンク | そのまま維持 | 決定的 |
| 6 | `## まとめ`, `## 結論`, `## Conclusion`, `## TL;DR` セクション | 見出し直下のブロックを `> [!summary]` callout で包む | 半決定的 |
| 7 | `## 注意`, `## 警告`, `## Caveats`, `## Warning` セクション | `> [!warning]` callout | 半決定的 |
| 8 | `## 補足`, `## メモ`, `## Note`, `## Notes` セクション | `> [!note]` callout | 半決定的 |
| 9 | `## 例`, `## Example`, `## サンプル` セクション | `> [!example]` callout | 半決定的 |
| 10 | `## FAQ`, `## よくある質問`, `## Q&A` セクション | `> [!question]` callout | 半決定的 |
| 11 | 記事中で 3 回以上出現するキー概念、または見出し化された固有用語 | `[[キー概念]]` で wikilink 化（初出のみ） | 判断 |
| 12 | 記事の主題から推測される 3〜5 個の話題 | frontmatter の `tags:` リストに追加（`#` プレフィクスは付けない、ネスト `area/topic` 可） | 判断 |
| 13 | `$inline$`, `$$display$$` の数式 | そのまま（Obsidian KaTeX 互換）。`$$` ブロックは前後に空行があることを保証 | 決定的（整形のみ） |
| 14 | 元 Markdown の `# タイトル` | frontmatter 直後に 1 行の `# タイトル` として残す（重複させない） | 決定的 |
| 15 | 同一 Vault 内ノートを示す内部参照（明示されている場合） | `[[note]]` または `[[note#見出し]]` 化 | 半決定的 |
| 16 | メタデータ箇条書きと本文を分けていた区切り線 `---` | frontmatter 化に伴い削除（frontmatter の `---` と区別する役割が無くなるため） | 決定的 |

## 半決定的ルールの判断指針

ルール 6〜10 (callout 化): 元見出しの意味が辞書定義通りに Callout type と一致する場合のみ適用する。例えば「## 補足情報として参考になるリンク集」のような「補足」を含むが内容が異なる見出しは callout 化しない。迷う場合は元のセクション構造を保つ。

ルール 15 (内部参照): 元 Markdown が Vault 内ノートへの相対パスリンクを明示しているときのみ適用。`[ホーム](/index.md)` のような明らかなナビゲーションは対象外。

## 判断ルールの指針

### ルール 11: Wikilink 候補

候補化の条件:
- 記事中で 3 回以上出現する（タイトル含めずカウント）
- 固有名詞、専門用語、製品名、人名、論文名、技術スタック名のいずれか
- 一般語（「方法」「結果」「データ」等）は除外
- 同じ記事内では初出のみ wikilink 化し、以降はプレーンテキストのまま（Obsidian は同名ノートを自動グルーピングする）

迷う場合は wikilink 化しない（後からノート作成時に追加可能）。

### ルール 12: タグ付け

選定基準:
- 記事の主題と直接関係する分野（例: `llm`, `prompt-engineering`, `database`）
- 記事の種類（例: `paper-summary`, `tutorial`, `experiment-log`）
- 必要に応じてネスト（例: `research/eval`, `programming/typescript`）

避けるべき:
- 記事タイトルそのもの（情報量がない）
- 一般語（`note`, `article`, `2026`）
- 数値のみ、特殊記号を含む文字列（Obsidian の Tag 仕様違反）

数は 3〜5 個。少なすぎ・多すぎは Vault 内検索性を損ねる。

## 自己検証チェックリスト

変換完了時に以下 7 項目を点検する。1 つでも未充足なら該当箇所を再修正する。

1. YAML frontmatter が valid（`---` で囲まれ、`title` / `source` / `date` / `tags` フィールドが存在し、値の型が型推論ルールに沿っている）
2. `# タイトル` 見出しが frontmatter 直後に 1 度だけ出現し、本文中に重複していない
3. Vault 内パスの画像がすべて `![[]]` 形式になっており、外部 URL 画像は標準 Markdown 形式を維持
4. 引用元情報がある場合 `> [!cite]` callout として配置されている
5. タグが 3〜5 個、`#` プレフィクスを frontmatter リスト内では付けていない、Tag 仕様（英数字 / `-` / `_` / `/`）に従う
6. 数式（`$$ ... $$`）の前後に空行があり、KaTeX 互換のコマンドのみ使用
7. 元記事の本文情報が欠落していない（callout 化や frontmatter 化で本文から取り除いた箇所が、frontmatter または callout 内に存在する）

## 変換時の禁止事項

- 元 Markdown に存在しない事実を frontmatter やタグに追加しない（タイトル・タグの推測値は元本文から導出可能な範囲に限る）
- 画像ファイル本体を移動・改名しない（Vault 内のリンク切れを起こすため）
- セクション本文の意訳・要約をしない（変換であって書き換えではない）
- callout 化したセクションの中身を勝手に短縮・要約しない
