# Codex の開発に関するガイドライン

## 基本原則

### ドキュメンテーション
- 絵文字を決して使用しないこと
- **で文字列を強調しないこと

## タスク管理

### タスク理解
- 新しいタスクを始める際は、まずタスク内容を明確に理解することが最重要です。
- 不明点があれば誤解したまま進めず、必ずユーザーに確認しましょう。

### 問題解決
- 同じ問題が繰り返し発生する場合は、原因を根本から突き止めましょう。
- 当てずっぽうに試したり「別のライブラリに変える／ダミー実装にする」と投げ出したりしないでください。

### タスク分割
- スコープが大きすぎる、または曖昧なタスクを受け取ったら、まず小さなサブタスクに分割できないか検討します。
- 分割が難しい、または疑問点が多すぎる場合はユーザーに働きかけ、タスクを細分化するよう依頼してください。

## コーディングスタイル

### Python
- python 3.12以上を前提
- 依存関係管理には uv を使用（pip は禁止）
- 全ての関数とメソッドに型アノテーションを記載
- mypy の型チェックを通すこと
- Google style の docstring を使用

### TypeScript / JavaScript
- ランタイムには Bun を使用
- オブジェクト定義には type エイリアスを使用（interface は不使用）
- any は使わず unknown を使用
- 型検証には zod を使用

## 言語設定
- ユーザーとのコミュニケーションは日本語で行うこと
- コード中のコメントやドキュメント文字列は英語で記述すること
